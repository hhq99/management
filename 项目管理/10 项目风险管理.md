## 一、章节核心概念

### 1. 项目风险的定义

项目风险是一种不确定的事件或条件，一旦发生，会对一个或多个项目目标产生正面或负面影响。已发生的消极风险可视为问题，问题又会引发新的风险。

风险四要素：起因、事件、概率、影响

### 2. 两类风险（考试重点）

- **单个项目风险**：一旦发生，会对一个或多个项目目标产生正面或负面影响的不确定事件或条件
  
- **整体项目风险**：不确定性对项目整体的影响，是相关方面临的项目结果正面和负面变异区间，源于包括单个风险在内的所有不确定性
  

单个项目风险 = 某一件独立的坏事 / 好事

整体项目风险 = 所有大大小小不确定事件叠加后，整个项目最终结局的波动范围

> **考试提示**：PMBOK中单独说“风险”通常指单个项目风险，除非上下文另有要求。考试中要注意区分题目问的是单个风险还是整体风险。

### 3. 风险管理目标

提高正面风险（机会）的概率和/或影响，降低负面风险（威胁）的概率和/或影响，从而提高项目成功的可能性。

### 4、风险类型

**风险后果：**

纯粹风险：只有两种结果 ——损失 / 无损失，绝对不可能获利

投机风险：三种结果 ——损失 / 无损失 / 获利，有赚钱可能性

## 二、七大管理过程（★★★★★）

PMBOK第六版风险管理包含7个过程，相比第五版增加了“实施风险应对”过程：

|     |     |     |
| --- | --- | --- |
| 过程  | 过程组 | 核心定义 |
| 11.1 规划风险管理 | 规划  | 定义如何实施项目风险管理活动 |
| 11.2 识别风险 | 规划  | 识别单个风险和整体风险来源并记录其特征 |
| 11.3 实施定性风险分析 | 规划  | 评估概率和影响，对风险进行优先级排序 |
| 11.4 实施定量风险分析 | 规划  | 量化分析风险对整体目标的综合影响 |
| 11.5 规划风险应对 | 规划  | 制定可选方案、选择应对策略并商定应对行动 |
| 11.6 实施风险应对 | 执行  | 执行商定的风险应对计划 |
| 11.7 监督风险 | 监控  | 跟踪已识别风险、监视残余风险、识别新风险、评估过程有效性 |

## 三、各过程详细知识点

### 过程1：规划风险管理（11.1）

**定义**：如何实施和开展项目风险管理活动的过程。

**工具&技术**：

专家判断

干系人分析：通过干系人分析确定项目干系人的风险偏好

会议：举办专门的规划会议来编制风险管理计划

**输出——风险管理计划**（包含以下11项内容，考试重点）：

1. **风险管理策略**：管理本项目风险的一般方法
  
2. **方法论**：确定具体方法、工具及数据来源
  
3. **角色与职责**：确定每项风险管理活动的领导者、支持者和团队成员
  
4. **资金**：确定风险管理活动所需资金，制定应急储备和管理储备使用方案
  
5. **时间安排**：确定实施风险管理过程的时间和频率
  
6. **风险类别**：使用风险分解结构（RBS） ——潜在风险来源的层级展现
  
7. **相关方风险偏好**：记录关键相关方的风险偏好
  
8. **风险概率和影响定义**：根据项目环境制定定性分析的标准
  
9. **概率和影响矩阵**：将风险划分为高、中、低级别
  
10. **报告格式**：风险登记册的内容和格式
  
11. **跟踪**：规定如何记录风险活动、如何进行风险审计
  

> **考试提示**：风险管理计划不是风险登记册，不要混淆。RBS是风险分类的工具，不是WBS。

### 过程2：识别风险（11.2）

**定义**：识别单个项目风险以及整体风险的来源，并记录其特征的过程。贯穿整个项目生命周期。

**主要工具与技术**：

- **核对单**：基于历史项目经验快速识别，但不全面，需关注项目的独特之处
  
- **假设条件与制约因素分析**：假设就意味着风险，需定期验证假设是否仍然成立
  
- **SWOT分析**：优势（Strengths）、劣势（Weaknesses）、机会（Opportunities）、威胁（Threats）
  
- **提示清单**：来源于RBS最低层，作为框架协助团队形成想法 **PESTLE/TECOP/VUCA**：用于识别整体项目风险来源的战略框架。
  

**输出**：

- **风险登记册**：记录已识别单个项目风险的详细信息（已识别风险清单、潜在应对措施、潜在风险责任人）
  
- **风险报告**：关于整体项目风险的信息及已识别单个项目风险的概述信息（渐进式编制）
  

### 过程3：实施定性风险分析（11.3）

**定义**：通过评估单个项目风险发生的概率和影响以及其他特征，对风险进行优先级排序。

本过程会为每个风险识别出责任人。

**工具与技术**：

- **风险数据质量评估**：评估风险数据的准确性、可靠性
  
- **风险概率和影响评估**：按风险管理计划中的定义进行评估（采用访谈或者会议的方式）
  
- **概率和影响矩阵**：将风险分为高、中、低优先级
  
- **风险分类**：按RBS等类别对风险进行分组
  
- **其他风险参数评估**：紧迫性、发生速度等
  

> **考试提示**：定性分析是所有项目都做的，定量分析不是必需的。

**输出：**

假设日志、问题日志、风险登记册更新、风险报告。

### 过程4：实施定量风险分析（11.4）

**定义**：就已识别的单个项目风险和其他不确定性的来源对整体项目目标的综合影响进行定量分析。

> **考试重点**：⚠️ 定量风险分析不是必要过程，在风险管理计划中会定义是否需要。

**关键输出变化**（第六版重要变化）：定量风险分析的输出不再是风险登记册，而是风险报告，描述整体风险情况。

### 过程5：规划风险应对（11.5）（★★★★★ 考试高频）

**定义**：为处理整体项目风险敞口以及应对单个项目风险，制定可选方案、选择应对策略并商定应对行动。

#### （一）威胁（消极风险）应对策略

|     |     |     |
| --- | --- | --- |
| 策略  | 核心含义 | 典型做法 |
| **规避** | 完全消除威胁 | 改变计划、缩小范围、改变策略、延长进度、关闭项目 |
| **转移** | 将风险责任转移给第三方 | 外包、买保险、找供应商 |
| **减轻** | 降低概率或影响 | 简化流程、更多测试、选择可靠供应商、加入冗余/备份 |
| **接受** | 承认风险存在，不主动采取措施 | 被动接受（事后处理/权变措施）；主动接受（建立应急储备） |
| **上报** | 超出项目经理权限时上报更高层 | 项目集、项目组合层面管理 |

#### （二）机会（积极风险）应对策略

|     |     |     |
| --- | --- | --- |
| 策略  | 核心含义 | 与威胁策略的对应关系 |
| **开拓** | 消除不确定性，确保机会出现 | 对应“规避” |
| **分享** | 将机会责任分配给能抓住机会的第三方 | 对应“转移” |
| **提高** | 提高发生概率或影响 | 对应“减轻” |
| **接受** | 机会发生时乐以利用，但不主动追求 | 对应“接受” |
| **上报** | 超出权限时上报 | 对应“上报” |

> **考试提示**：务必记住威胁和机会五组策略的对应关系——开拓↔规避、分享↔转移、提高↔减轻、接受↔接受、上报↔上报，这是高频考点。

#### （三）其他重要概念

- **应急应对策略**：只在某些预定条件发生时才能实施的计划，又称应急计划或应急预案
  
- **次生风险**：实施风险应对措施而直接导致的风险
  

输出：变更请求、项目管理计划更（包含3大基准）

### 过程6：实施风险应对（11.6）

**定义**：执行商定的风险应对计划的过程。

> **考试提示**：这是第六版新增的过程。属于执行过程组。注意区分“规划风险应对”（规划阶段制定计划）和“实施风险应对”（执行阶段执行计划）。

### 过程7：监督风险（11.7）

**定义**：在整个项目期间，监督商定的风险应对计划的实施、跟踪已识别风险、识别和分析新风险，以及评估风险管理过程的有效性。

**工具与技术**：

- **技术绩效分析**：比较技术成果与计划目标
  
- **储备分析**：确定应急储备和管理储备的使用情况
  
- **风险审计**：评估风险管理过程的有效性
  
- **会议**：风险审查会（审查风险应急方案）
  

**重要概念区分**：

|     |     |     |     |
| --- | --- | --- | --- |
| 储备类型 | 应对风险类型 | 是否在成本基准中 | 项目经理权限 |
| **应急储备** | 已知-未知风险 | ✅ 包含在成本基准中 | 项目经理可直接使用 |
| **管理储备** | 未知-未知风险 | ❌ 不在成本基准中 | 需提出变更请求后才能使用 |

> **考试提示**：监督风险过程中如果发现风险应对无效或出现新风险，需要更新风险登记册和风险报告。

输出：变更请求、风险登记册更新、风险报告

## 四、两大核心输出物对比（考试高频）

|     |     |     |
| --- | --- | --- |
|     | 风险登记册 | 风险报告 |
| **关注点** | 单个项目风险 | 整体项目风险 |
| **内容** | 已识别风险清单、潜在应对措施、风险责任人 | 整体风险信息及单个风险的概述 |
| **编制** | 从识别风险开始建立 | 渐进式编制 |

## 五、考试高频考点总结

### 必背要点

1. **7个过程**的名称、所属过程组（规划6个 + 执行1个 + 监控1个）
  
2. **威胁5策略**（规避、转移、减轻、接受、上报）与机会5策略（开拓、分享、提高、接受、上报）的对应关系
  
3. **应急储备**（已知-未知，在基准中，PM可直接用）vs 管理储备（未知-未知，不在基准中，需变更请求）
  
4. **风险登记册**（单个风险）vs 风险报告（整体风险）
  
5. 定量风险分析不是必须的，定性分析**是必须的**
  
6. **实施风险应对**是第六版新增过程
  
7. 识别风险**贯穿整个项目生命周期**
  

### 常见考试陷阱

- 风险登记册 ≠ 风险管理计划
  
- 风险审计（监督风险的工具）≠ 质量审计
  
- 上报策略不是消除风险，而是转移管理责任到更高层
  
- 被动接受 ≠ 不作为——风险发生后要采取权变措施
  
- 减轻是降低概率或影响，不是消除（规避才是消除）
