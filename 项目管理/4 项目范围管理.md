### 一、核心概念

**项目范围管理**的核心目标是确保项目“做且只做”成功完成项目所需的全部工作。它主要定义和控制哪些工作应包含在项目内，哪些不应包含在内。

需要区分两个概念：

- **产品范围**：某项产品、服务或成果所具有的特性和功能。
  
- **项目范围**：为交付具有规定特性与功能的产品、服务或成果而必须完成的工作。
  

---

### 二、六个管理过程

本章包含6个过程，按所属过程组划分如下：

|     |     |     |
| --- | --- | --- |
| 过程  | 所属过程组 | 核心目的 |
| **5.1 规划范围管理** | 规划  | 创建范围管理计划和需求管理计划 |
| **5.2 收集需求** | 规划  | 确定、记录并管理干系人的需要和需求 |
| **5.3 定义范围** | 规划  | 制定项目和产品的详细描述 |
| **5.4 创建WBS** | 规划  | 将可交付成果和工作分解为更小的组件 |
| **5.5 确认范围** | 监控  | 正式验收已完成的可交付成果 |
| **5.6 控制范围** | 监控  | 监督范围状态，管理范围基准变更 |

---

#### 5.1 规划范围管理

- **定义**：创建范围管理计划，书面描述如何定义、确认和控制项目范围
  
- **输出**（两个计划）：
  
  - **范围管理计划**：描述如何定义、制定、监督、控制和确认项目范围（如何编写范围说明书、如何创建WBS、如何验收等）
    
  - **需求管理****计划**：描述如何分析、记录和管理项目需求
    
- **工具**：专家判断、备选方案分析、会议
  

---

#### 5.2 收集需求

- **定义**：为实现项目目标而确定、记录并管理干系人需要和需求的过程
  
- **输出**：
  
  - **需求文件**：包含需求描述、分类、排序、验收标准等
    
  - **需求跟踪矩阵**：将需求与高层目标、WBS成果关联起来，把产品需求从其来源连接到能满足需求的可交付成果的一种表格。（来源：业务目标 → 需求文件 → WBS 可交付成果 → 测试用例。）
    
- **工具与技术**（考试重点）：
  

|     |     |     |     |
| --- | --- | --- | --- |
| 类别  | 工具  | 要点  | 备注  |
| **数据收集** | 访谈、焦点小组、问卷调查、标杆对照 | 标杆对照可来自内部或外部 | <br> |
| **决策**<br><br><br> | 投票（大多数/相对多数/一致同意/独裁）、多标准决策分析 | 德尔菲技术=一致同意+匿名+多轮 | <br> |
| **数据表现** | 亲和图（归纳分类）、思维导图（演绎法） | <br> | <br> |
| **人际关系** | 名义小组技术（头脑风暴+投票排序）、观察/交谈、引导式研讨会 | 引导式研讨会=跨职能快速定义需求 | <br> |

---

#### 5.3 定义范围

- **定义**：制定项目和产品详细描述的过程
  
- 输入是需求文件
  
- **输出**：项目范围说明书，包含：
  
  - 产品范围描述：对项目范围、主要可交付成果、假设条件和制约因素的描述
    
  - 可交付成果
    
  - 验收标准
    
  - **项目的除外责任**（明确不做什么——有助于管理期望、减少范围蔓延）
    
- **工具**：专家判断、产品分析、备选方案生成、引导式研讨会
  

---

#### 5.4 创建WBS（创建工作分解结构）

- **定义**：将项目可交付成果和项目工作分解为更小、更易于管理的组件，
  
- WBS的最底层的组件称为工作包，WBS中的“工作” 代表了作为活动结果的工作产品或可交付成果，而非活动本身。可对其进行成本和持续时间进行估算和管理
  
- 分解是把项目范围和可交付成果逐步划分为更小、更便于管理的组成部分的技术。分解的程度取决于所需的控制程度，以实现对项目的高效管理（首先要分析和识别可交付成果）
  
- **输出**：范围基准（由项目范围说明书 + WBS + WBS词典组成）
  
- **WBS核心原则**（考试重点）：
  
  - **100%规则**：下一层级之和必须100%代表上一层级
    
  - 面向可交付成果，非面向活动
    
  - 层次结构通常4-6层
    
  - 每个元素有唯一标识符
    
  - 不显示工作顺序或依赖关系
    
- **WBS词典**：为每个WBS元素提供详细描述（工作描述、负责人、里程碑、资源、成本、质量标准等）
  
- **范围基准**：范围基准是经过批准的范围说明书、WBS和WBS词典。
  

---

#### 5.5 确认范围

- **定义**：正式验收已完成的项目可交付成果的过程
  
- **关键点**（高频考点）：
  
  - 属于**监控过程组**
    
  - **需要客户或发起人参与**
    
  - 应定期进行，不仅限于项目结束时
    
  - **与质量控制不同**：确认范围关注验收（外部客户），质量控制关注正确性（内部检查）
    
- **输出**：验收的可交付成果、工作绩效信息、变更请求
  

---

#### 5.6 控制范围

- **定义**：监督项目和产品范围状态，管理范围基准变更的过程
  
- **核心关注**：防止范围蔓延（未经控制的范围变更）1、确定偏离范围基准的原因和程度 2、决定是否需要采取纠正或预防措施
  
- **工具**：
  
- 偏差分析：将基准与实际结果进行比较，确定偏差是否出于临界值区间内，或是否有必要采取纠正或预防措施
  
- 趋势分析：审查项目绩效随时间的变化情况，以判断绩效是正在改善还是恶化
  
- 变更控制工具
  
- **输出：**
  
- 工作绩效信息、变更请求、项目管理计划更新、项目文件更新
  

控制质量（核实的可交付产物）-确认范围（验收的可交付物）-结束项目或者阶段

---

### 三、考试高频考点速记

1. **六个过程的顺序**：规划范围管理 → 收集需求 → 定义范围 → 创建WBS → 确认范围 → 控制范围
  
2. **范围基准三件套**：项目范围说明书 + WBS + WBS词典
  
3. **确认范围 vs 质量控制**：确认范围=验收（客户参与），质量控制=正确性（内部）
  
4. **范围蔓延**：未经控制的范围变更——控制范围过程的核心防范对象
  
5. **100%规则**：WBS的核心原则，下一层必须100%覆盖上一层
  
6. **项目范围说明书**必含内容：产品范围描述、可交付成果、验收标准、除外责任
  

# 极简逻辑链条浓缩版（背诵版）

1. 规划范围管理：制定做事制度；
  
2. 收集需求：整理客户需求清单；
  
3. 定义范围：敲定项目做什么和不做什么；
  
4. 创建 WBS：拆分成果形成范围基准；
  
5. 确认范围：客户阶段性验收交付物；
  
6. 控制范围：对照基准，管控范围变更。
