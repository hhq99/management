## 一、章节总览

项目进度管理包括为管理项目按时完成所需的六个过程：

1. **规划进度管理**（规划过程组）
  
2. **定义活动**（规划过程组）
  
3. **排列活动顺序**（规划过程组）
  
4. **估算活动持续时间**（规划过程组）
  
5. **制定进度计划**（规划过程组）
  
6. **控制进度**（监控过程组）
  

---

## 二、各过程详解

### 过程1：规划进度管理（6.1）

**定义**：为规划、编制、管理、执行和控制项目进度而制定政策、程序和文档的过程。

**作用**：为如何在整个项目期间管理项目进度提供指南和方向。

**输入**：项目章程、项目管理计划（范围管理计划、开发方法）、事业环境因素、组织过程资产

**工具与技术**：专家判断、数据分析（备选方案分析）、会议

**输出**：进度管理计划——项目管理计划的组成部分，规定：

- 项目进度模型制定（关键路径法）
  
- 计量单位、准确度
  
- 控制临界值（允许出现的最大进度偏差）
  
- 绩效测量规则（EVM规则：SV、SPI）
  
- 报告格式
  

> **考试要点**：进度管理计划是“管理进度的方法论”，不是具体的时间表。区分“进度管理计划”和“项目进度计划”。

---

### 过程2：定义活动（6.2）

**定义**：识别和记录为完成项目可交付成果而需采取的具体行动的过程。

**作用**：将工作包分解为进度活动，作为估算、规划、执行、监督和控制的基础。

**输入**：进度管理计划、范围基准（关键输入）

**工具与技术**：

- **分解**：把工作包分解成活动，建议让团队成员参与
  
- **滚动式规划**：近期工作详细规划，远期工作粗略规划，渐进明细
  
- 专家判断、会议
  

**输出**：

- **活动清单**：包含项目所需的全部进度活动的综合清单
  
- **活动属性**：每项活动的多重属性（名称、紧前/紧后活动、资源需求等）
  
- **里程碑清单**：列出所有里程碑，指明强制性还是选择性
  

> **考试要点**：
> 
> - **里程碑持续时间为0**，只代表时间点/事件，不是可交付成果
>   
> - **滚动式规划**是渐进明细的具体体现，属于适应型/敏捷的规划方式
>   

---

### 过程3：排列活动顺序（6.3）

**定义**：识别和记录项目活动之间关系的过程。

**作用**：定义工作之间的逻辑顺序，在制约因素下获得最高效率。

**工具与技术**：

**（1）紧前关系绘图法（PDM）** —— 又称前导图法/单代号网络图（AON）

- 节点=活动，箭头=逻辑关系
  
- **四种逻辑关系**：
  
  - **FS（完成-开始）** ：最常用

#### 例子 1（装修）

A：刷墙面腻子 B：墙面刷乳胶漆 必须腻子干透完工，才能开始刷漆 → FS 关系

- **FF（完成-完成）**

#### 例子 1（写书）

A：正文内容撰写 B：配图插画绘制 可以一边写一边画图，但正文全部写完前，插画不能全部收尾定稿 → FF 正文不完，插画不能最终交付。

- **SS（开始-开始）**

#### 例子 1（修路工程）

A：开挖路基（持续 10 天） B：铺设水管（持续 8 天） 路基开挖第 1 天开工后，不需要等全部挖完，挖一段就能同步铺水管，两者并行 → SS

- **SF（开始-完成）**

#### 经典例子（夜班交接）

A：白班人员上岗（开始） B：夜班人员下班（完成）

**（2）确定和整合依赖关系**——四种依赖关系：

|     |     |     |
| --- | --- | --- |
| 类型  | 说明  | 可控性 |
| **强制性依赖**（硬逻辑） | 工作内在性质决定，不能违反 | 不可控 |
| **选择性依赖**（软逻辑） | 基于最佳实践，团队可自由选择 | 可控  |
| **外部依赖** | 项目活动与非项目活动之间 | 不可控 |
| **内部依赖** | 项目活动之间 | 可控  |

**（3）提前量和滞后量**

- **提前量**：紧后活动可以提前的时间
  
- **滞后量**：紧后活动需要推迟的时间（如FS+3表示滞后3天）
  

> **考试要点**：
> 
> - **路径汇聚**处风险最大
>   
> - 提前量和滞后量不能替代进度逻辑关系
>   

# 一、什么是路径汇聚（路径汇合）

## 定义

多条独立活动路径，最终汇集到同一个紧后活动，这个交汇点就叫路径汇聚。 简单说：一个活动，有两个及以上紧前活动，多条线路都要走到它这里，就是路径汇聚。

## 核心逻辑

要启动这个汇聚点的活动，所有前置路径必须全部完成，只要任意一条路径延误，整个活动都会延期。

## 举例理解

### 装修场景

路径 1：水电改造 → 水管试压 路径 2：墙面找平 → 腻子施工 两条路径最终汇聚到同一活动：全屋刷乳胶漆 刷漆是汇聚点，必须：水管试压完工 + 腻子施工完工，才能开始刷漆。 只要水电没做完，或者腻子没干透，刷漆都没法开工。

### 软件项目场景

路径 A：前端页面开发 路径 B：后端接口开发 两条路径汇聚到：前后端联调测试 联调属于路径汇聚点，前端、后端两条线全部做完，才能启动联调。

**输出**：项目进度网络图，表示项目进度活动之间的逻辑关系的图形

### 过程4：估算活动持续时间（6.4）

**定义**：根据资源估算结果，估算完成单项活动所需工作时段数的过程。

**工具与技术**：

|     |     |     |     |
| --- | --- | --- | --- |
| 工具  | 特点  | 准确性 | 备注  |
| **类比估算** | 自上而下，成本低、速度快 | 较低  | 参考历史或者相似项目 |
| **参数估算** | 基于历史数据和公式/统计关系 | 取决于数据质量 | <br> |
| **三点估算（PERT）** | 考虑不确定性和风险 | 较高  | <br> |
| **自下而上估算** | 从下到上逐层汇总 | 最准确（但慢） | <br> |

**三点估算公式**：

- **三角分布**：（最悲观 + 最乐观 + 最可能）/ 3
  
- **贝塔分布**（默认使用）：（最悲观 + 最乐观 + 最可能 × 4）/ 6
  

**储备分析**：

- **应急储备**：应对“已知-未知”风险，包含在进度基准内
  
- **管理储备**：应对“未知-未知”风险，不包含在进度基准内
  

**输出**：持续时间估算、估算依据、

### 过程5：制定进度计划（6.5）—— **考试重中之重**

**定义**：分析活动顺序、持续时间、资源需求和进度制约因素，创建项目进度模型的过程。

**核心工具与技术**：

**（1）关键路径法（CPM）**

在不考虑资源限制的前提下，顺着逻辑关系估算活动，计算最早开始、最早完成、最晚开始、最晚完成时间以及总时差，识别出关键路径。

- **关键路径**：项目中时间最长的路径，决定项目最短工期
  
- **总浮动时间（总时差）** = LS - ES = LF - EF
  
- 关键路径的总浮动时间最少，通常为0（也可能为正或负）
  
- **关键路径越多，风险越大**；次关键路径越接近关键路径，风险越大
  

- ES：最早开始时间（尽可能早开工）
  
- EF：最早完成时间（EF=ES+活动持续时间）
  
- LS：最晚开始时间（再晚开工就延误总工期）
  
- LF：最晚完成时间（最迟完工，不拖整体项目工期）
  

1. ：推迟多久开工，依然不会耽误整个项目完工。
  
2. ：推迟多久完成，依然不会耽误整个项目完工。
  

- 非关键路径：总时差＞0，可以偷懒延后；
  
- 如果总时差＜0：代表进度落后，需要赶工。
  

**（2）资源优化**

- **资源平衡**：有效优化资源，但**可能改变关键路径**
  
- **资源平滑**：不改变关键路径，但无法实现所有资源优化
  

1. 用大白话解释

### ①资源平衡

举例：关键路径任务 A 和非关键任务 B 本来安排在同一时间段，共用同一个工程师，工程师忙不过来。 现在只能把 B 往后挪很久，B 推迟过多，最后这条线路工期变长，变成新的关键路径。

> 结论：为了解决资源超负荷，被迫占用全部时差甚至压缩关键路径活动，**关键路径发生变化，总工期变长**。

### ②资源平滑

非关键活动有富余时间（总时差），我只在时差范围内往后挪。 例：任务总时差 3 天，最多往后推迟 3 天。

- 只要不超出总时差：关键路径不变，项目完工时间不变；
  
- 弊端：如果资源缺口很大，可利用时差不够，依然还是会出现资源超负荷。 因此：**没法做到全部资源均衡**。
  

2. 做题判断口诀（背下来）
  
3. 资源平衡：解决资源过载 → **关键路径改变，工期可能延长**
  
4. 资源平滑：只用总时差 → **关键路径不变，工期不变，但资源不能完全优化**
  

**（3）进度压缩**

- **赶工**：加班、加资源→成本增加，选择成本增加最小的活动，对关键路径上的活动赶工
  
- **快速跟进**：顺序活动改为并行→风险增加，只适用于选择性依赖关系的活动，对关键路径上的活动使用
  

> **优先级**：题目无限制时，优先选择**进度压缩 > 赶工 > 快速跟进**

**（4）数据分析**

- **假设情景分析**、模拟（蒙特卡洛分析） ——得到项目完成时间的概率分布

### 对比区分（PMP 做题核心）

1. **假设情景分析：人设定有限场景，得到若干个完工时间，没有概率；**
  
2. **蒙特卡洛：计算机大批量随机模拟，输出概率（多少可能性哪天做完），结果是概率分布曲线。**
  

**输出**：

- **进度基准**（经批准的项目进度计划）
  
- **项目进度计划**（三种形式）：
  
  - **里程碑进度计划** → 向客户汇报
    
  - **概括性进度计划（横道图/甘特图）** → 向管理层汇报
    
  - **详细进度计划（项目进度网络图）** → 团队内部使用

### 过程6：控制进度（6.6）

**定义**：监督项目状态，以更新项目进度和管理进度基准变更的过程。

**考试补充**（PMP常考两个心理学定律）：

- **帕金森定律**：只要还有时间，人们就会不必要地工作直到用完所有时间
  
- **学生综合征**：拖延症，到最后一刻才开始工作
  

输出：工作绩效信息、进度预测、变更请求、项目文件更新

## 三、进度计划方法（考试高频）

|     |     |
| --- | --- |
| 方法  | 说明  |
| **关键路径法（CPM）** | 传统预测型项目的主流方法 |
| **迭代型进度计划** | 适应型/敏捷方法，滚动式规划，用户故事优先级排序，时间盒内开发 |
| **按需进度计划** | 看板体系，拉动式进度计划，根据团队交付能力限制进行中的工作 |

## 四、高频考点速记清单

|     |     |
| --- | --- |
| 考点  | 关键记忆点 |
| 里程碑 | **持续时间=0**，是时间点不是活动 |
| 滚动式规划 | 近期详细、远期粗略，**渐进明细** |
| PDM四种关系 | **FS最常用**，记住SS/FF/SF |
| 四种依赖 | 强制性（硬）、选择性（软）、外部、内部 |
| 三点估算 | **默认用贝塔分布**：（P+O+4M）/6 |
| 应急储备 vs 管理储备 | 应急=已知-未知（在基准内）；管理=未知-未知（不在基准内） |
| 关键路径 | **总浮动时间最少**（通常为0），决定项目工期 |
| 资源平衡 vs 资源平滑 | 平衡可能改变关键路径；平滑不改变关键路径 |
| 赶工 vs 快速跟进 | 赶工=加成本；快速跟进=加风险 |
| 进度计划三种形式 | 里程碑→客户；甘特图→管理层；网络图→团队 |
